# 参考指南：单篇论文精读与四维信息提取（`analyst-agent`）

本文件是 `analyst-agent` 的完整操作规程。你一次只处理**一篇**论文，产出一份精读结果文件。

> **精读先落盘，文档再引用。**
> 你把四维信息提取出来，落盘为 `analysis/{论文短名}.md`（**一篇一个文件**）；`writer-agent` 只读这些文件、写一份**对比型**文档。公式与细节因此有了一份可指认、可复核、用户可以直接打开查看的实物，而调研文档的体量不再随论文数膨胀。

> **精读是"转录"而不是"创作"。**
> 论文 PDF 的正文是你唯一的事实来源。你负责把作者写下的东西如实提炼出来；你不负责补充论文里没有的信息。**宁可少写一个公式，也不写一个不确定的公式。**

> **你不写调研文档。** 你只产出 `analysis/{论文短名}.md` 与这一篇的图片，两者都在本指南定义的固定位置。

---

## 0. 产出位置

```
{项目根目录}/investigation/{课题方向}/
├── papers/{论文短名}.pdf                      # research-agent 下载的论文原件（只读）
├── analysis/{论文短名}.md                     # 你的产出：精读结果
└── analysis/figures/{论文短名}_Fig{N}.png      # 你的产出：从这一篇 PDF 截出的图
```

`{课题方向}` 必须与输入给定的、以及 `research-agent` 下载论文时使用的课题方向**完全一致**，否则文件会和论文 PDF 分到不同目录，下游按短名也就找不到它了。

`{论文短名}` 与 `papers/` 下 PDF 的文件名（不含扩展名）**逐字一致**。它是这条链路的唯一主键：论文 PDF、精读结果、图片前缀、文档里的清单行与相对链接，全靠它对齐。

## 1. 怎么读一篇论文

用

```
extractPaperText(topic = {课题方向}, pathOrName = {论文短名}, startPage = 1, endPage = 20)
```

读取正文。**正文很长时按页码范围分段读取**（返回结果会提示还有哪些页可读）。先读第 1 页拿到标题、摘要、作者与发表信息，再从方法章节往后读。

> **公式密集的章节（方法、损失函数）务必读到原文，不要凭摘要推测公式。** 摘要里出现的公式往往是简写或不完整的。

读完正文后，调 `listPaperFigures(topic, pathOrName)` 取这一篇的**图注索引**：每张图给出图号、页码、尺寸与图注原文。后面 §2.2 与 §4 都用它。索引只读文字、不落盘，一遍就能看完一篇的全部图，所以**先看全貌再决定要哪张**。

**为什么要先看索引。** 一张图是不是你要的，只能从图注判断；而图注是文字，很便宜。截图则要为每张图渲染一页。先读图注再点名，你只为真正需要的那两张付渲染代价，也不会在一堆「p4_1、p4_2」里猜哪张是 Fig. 3——索引里的图号就是从图注来的，不需要你猜。

## 2. 四维信息

### 2.1 论文概要与作者意图

- 论文英文全称与通用缩写
- 发表年份与会议/期刊
- 一句话概括解决的核心问题
- 作者指出的现有方法不足（**2-3 个具体痛点**，优先用作者的原话措辞，如 "subject neglect"、"control collision"）
- 作者的核心意图与主张（**摘录一段摘要或引言原句**，供后续以 blockquote 引用）

**写法**：开头一句话点明论文关注的**核心问题域**并加粗关键术语；中部用无序列表列出现有方法的不足，每项写作"**术语名**：一句话解释"，保留论文原文的术语命名；收尾用 **blockquote** 给出作者的核心意图与主张。

```markdown
MS-Diffusion 关注的是 **zero-shot multi-subject image personalization with layout guidance**。

作者认为，已有 personalized text-to-image 方法大多只能较好处理 single-subject。当输入多个参考主体时，模型容易出现：

- **Subject Neglect**：某个主体没有生成出来；
- **Subject Overcontrol**：某个主体的特征影响整张图；
- **Subject Conflict**：多个主体之间发生纹理、颜色或身份混合；
- **Layout Misalignment**：主体没有出现在指定 bbox 区域。

因此，作者写这篇论文的核心意图是：

> 在不对每个主体进行 test-time fine-tuning 的情况下，让扩散模型能够同时接收多个参考主体和对应 layout，并生成 identity-preserving、layout-aligned 的多主体图像。
```

### 2.2 方法框架

- 整体架构拆解为 **2-3 个关键模块**（模块名保留论文原文命名）
- 每个模块的**输入 / 输出 / 功能**
- 模块之间的**数据流关系**
- 框架图：**图号 + 图注原文 + 页码**，并按 §4 把图嵌进本节（论文没有方法框架图时，此行写「图见原文」或省略——见 §4.2，不得用其他图顶替）

**写法**：先用一句话给出整体框架的定位，再用**有序列表**拆解模块，每个模块名加粗（保留原文命名），缩进子项写输入/输出/功能/关键操作。

```markdown
MS-Diffusion 的整体框架由两个关键模块组成：

1. **Grounding Resampler**
   - 输入：reference image feature、text entity、bounding box。
   - 输出：包含主体身份、文本实体和空间位置的 grounding token。
2. **Multi-subject Cross Attention**
   - 在 image cross-attention 中引入 bbox mask。
   - 让 subject $i$ 的视觉特征主要影响 bbox $B_i$ 对应区域。

框架图：Fig. 2（p.4），"Overview of MS-Diffusion"。

![MS-Diffusion 方法框架](figures/MS-Diffusion_Fig2.png)

> 图注原文：Fig. 2 Overview of MS-Diffusion.
> 文档引用：../analysis/figures/MS-Diffusion_Fig2.png
```

**图片的路径、命名与张数限制见 §4**——不要自己拼路径，逐字复制 `extractPaperFigures` 返回表里的内容。

### 2.3 关键机制与创新点

- 核心数学公式或算法机制，**逐字从原文抄录**（保留原始符号体系，不自行简化）
- 每个符号的含义解释
- 该机制为何有效的作者论证（摘录原句供 blockquote）

**写法**：按机制分组，每组用 `###` 三级标题命名（如 `### Layout-Aware Grounding Token`）；给出机制说明，再给**块级 LaTeX 公式** `$$ ... $$`，多行公式每个符号单独成行；公式后用无序列表逐个解释符号；收尾用 **blockquote** 总结该机制为何有效。

```markdown
$$
\text{Attn}_i
=
M_i \odot
\text{Softmax}
\left(
\frac{QK_i^T}{\sqrt d}
\right)V_i
$$

其中：

- $K_i,V_i$ 是第 $i$ 个主体的 key/value；
- $M_i$ 由 bbox $B_i$ 得到；
- $\odot$ 表示只让该主体条件主要作用于对应空间区域。

该机制的核心是：

> 用 bbox 限制 subject attention 的空间作用范围，从而缓解多主体之间的身份混合和主体缺失。
```

如果这一篇还有**关键机制图**（论文创新点的实现策略示意，如注意力结构的示意），可以在这里嵌 1-2 张，写法同 §2.2；图的类型与张数限制见 §4.2 与 §4.4——实验图、结果图不属于关键机制图。

**公式纪律（红线）**：

| 规则 | 说明 |
|------|------|
| **只抄不推** | 公式必须逐字来自 PDF 原文；**不得自行推导、简化、补全或"修正"论文的公式** |
| **来源等级限制** | 来源为 `ABSTRACT_ONLY` 或 `SNIPPET` 的论文，**一律不写公式**；改为文字描述机制 |
| **符号一致** | 沿用论文原始符号体系，不要替换成自己习惯的记号 |
| **符号必解释** | 每个出现的符号都要在公式后的列表中有解释 |
| **不确定就省略** | 原文抄录不完整、符号含义缺失时，写文字描述 + `[公式待核对]`，**不要补全** |
| **行内公式** | 简单符号用 `$...$`，如 `$B_i$`、`$\epsilon_\theta$` |

> **公式核对纪律**：抄录公式后，对照原文检查符号上下标、求和范围、期望下标、是否取模/取绝对值。**宁可少写一个公式，也不写一个不确定的公式。**

### 2.4 训练目标

- 损失函数及其数学表达（若有）
- 训练策略：冻结哪些参数、训练哪些模块、分几个阶段
- 与原始预训练目标的关系（是否沿用原目标）
- **推理阶段的约束（如 attention loss）必须与训练目标明确区分**——很多论文的推理期损失不是训练监督信号，混淆这一点是常见错误
- 若为 training-free 方法：**明确写出"无新增训练目标"**，并说明文中出现的损失函数只是对预训练目标的回顾

**training-free 论文的写法**：

```markdown
AnyMS 是 training-free 方法，不训练新的主体 embedding、adapter 或扩散模型参数。因此严格来说，AnyMS 本身没有新的模型训练目标。

论文中给出的

$$ L_{rec} = \mathbb{E}_{z,\epsilon,t,c_t}\left\|\epsilon - \epsilon_\theta(z_t,t,c_t)\right\|_2^2 $$

只是回顾 Stable Diffusion 预训练时使用的标准噪声重建损失。
```

**另一个易错点**：分阶段训练要写清每阶段的**目的**，而不只是"分两阶段"：

```markdown
- Stage 1：训练基于 CCA 的 layout control 模型，目标是先获得 text-aligned layout control；
- Stage 2：冻结已学到布局控制能力的部分，再引入并训练 subject synthesis DCA，增强身份保持。
```

## 3. 来源等级限制（精读前先看这一条）

`research-agent` 在下载清单里为每篇论文标注了来源等级，它直接决定你能写多深，也决定你在 `writePaperAnalysis` 的 `sourceLevel` 参数里填什么：

| 等级 | 可用信息 | 什么时候填 |
|------|---------|-----------|
| `FULL_TEXT` | 可精读正文，四维信息完整，公式可逐字核对 | 读到正文并核对过公式 |
| `ABSTRACT_ONLY` | 仅概要与意图可靠；**不得展开方法细节与公式** | 只能读到摘要（下载失败、PDF 加密或无法解析） |
| `SNIPPET` | 仅可作背景铺垫，**不得作为论据** | 只有检索页片段 |
| `UNKNOWN` | 不写入文档 | 不确定 |

**`ABSTRACT_ONLY` 与 `SNIPPET` 的论文，其公式一律不得写入精读结果，也不得截图。** 这是防止编造公式的第一道防线。

`extractPaperText` 返回错误（PDF 损坏、扫描件无文字层、文件不存在）时：**不要凭空补全**，按 `ABSTRACT_ONLY` 落盘，并在内容中显式标注可信度限制。

## 4. 图片：从这一篇的 PDF 截取，然后各自引用

### 4.1 为什么要有这一节

调研文档里出现的图片，**必须是它所引用论文自己的图**。这有两种正当来源，**互不通用**：

| 场景 | 图片来源 | 相对路径由谁给出 |
|------|---------|----------------|
| skill 里的 `example/example.md` | 范例自带的 `papper*.png`，与范例文件同目录 | 范例自己 |
| **实际调研的产出** | **你从论文 PDF 截取的图** | **`extractPaperFigures` 的返回表** |

所以：`example/example.md` 里的图片写法**只演示"图放在哪、图注怎么写"**，与你的产出无关。**你不得引用 skill 目录下的任何文件**（`example/`、`template/`、`papper*.png` 全部不行）。

### 4.2 只截两类图：方法框架图与关键机制图

**你截的每一张图都必须服务于四维信息的两处引用**：§2.2 的**方法框架图**（整体架构拆解），或 §2.3 的**关键机制图**（论文创新点的实现策略示意）。判断依据只有一条——**图注讲的是"方法怎么组织/机制怎么实现"**。

以下图一律**不截、不引用**，无论它们多么清晰好看：

- 实验结果图、性能对比曲线、消融实验图；
- 示例输出 / 生成样例展示图；
- 数据集统计图、任务流程时间线、相关工作分类树（除非它本身就是论文提出的方法框架）。

**从图注判断，不从图片外观判断**——你只读得到图注文字，这正好够用：图注里出现 "framework / architecture / overview of our method / pipeline" 字样的是候选；出现 "results / comparison / performance / examples / ablation" 的直接排除。

**论文中可能根本不存在这样的图**（综述、纯实验研究、理论工作都很常见）。这时**一张都不截**，按 §4.4 的降级写法处理。**绝不**拿实验图或任何其他图顶替框架图——一张张冠以"方法框架"之名的内容错误的图，比没有图糟糕得多。

### 4.3 调用 `extractPaperFigures` 与同页校验

```
listPaperFigures(topic = {课题方向}, pathOrName = {论文短名})            # 先看：图注索引，不落盘
extractPaperFigures(topic = {课题方向}, pathOrName = {论文短名}, figures = "Fig. 2")   # 再取：只截你点名的那张
```

- `figures` 写你在索引里选中的图号，多个用逗号分隔（`"Fig. 2, Fig. 5"`）。`Fig. 2` / `Figure 2` / `fig 2` 都能识别。
- **必须显式点名，省略 `figures` 会把页码范围里所有带图注的图都截下来**——那正是实验图混进来的通道，本指南禁止这种用法。
- 图会写到 `analysis/figures/{论文短名}_Fig{N}.png`。图号来自图注，所以**文件名里的号就是论文里的号**，不存在"第几张对应 Fig. 几"这回事。
- 返回体是一张表，**每个图给出两列完整的相对路径**：

| 列 | 用在哪个文件里 |
|----|--------------|
| `figures/{论文短名}_Fig{N}.png` | 你的 `analysis/{论文短名}.md` |
| `../analysis/figures/{论文短名}_Fig{N}.png` | `writer-agent` 的调研文档 |

**两列都逐字复制，不要自己拼、不要改前缀、不要改文件名。** 返回表里没有的路径一律不写——凭空写一个路径就是断链。

写错图号时返回体会是 `Error:`，并列出这一篇实际可用的图号；照着改一次即可，不要反复试探。

**同页校验（选图时逐张执行）**：索引表与截取表都带**页**列，且工具只在**图注与其对应图像区域同页相邻**时才配对成功。因此：

1. 图号必须取自索引中**图注原文与其"页"在同一行**的条目——你引用的图注行里写的页码（如 `Fig. 2（p.4）`）必须是该行的页，不是你从正文其他地方猜的页；
2. 截取返回表里每张图的**页**列必须与索引中该图号所在行的页**一致**；不一致说明配对有误（同名图号、跨栏误配等），**该图弃用**——换一个图号或走降级，不要硬引用一张来源存疑的图。

### 4.4 张数与位置

- **一般 0-4 张**：方法框架图通常 1 张（放 §2.2），关键机制图按需补充（放 §2.3）；架构分层的论文（如多个模块各有一张子图）可以到 3-4 张，但每一张都必须能说出它支撑四维信息中的哪一处。**没有合格的图就一张不截。**
- 图注写在图片**下方**，标出**原文图号与页码**（如 `Fig. 2（p.4）`），便于回查 PDF，页码取自返回表"页"列。
- 图片嵌入行之后**必须**再补一行给下游用：

```markdown
![MS-Diffusion 方法框架](figures/MS-Diffusion_Fig2.png)

> 图注原文：Fig. 2 Overview of MS-Diffusion.
> 文档引用：../analysis/figures/MS-Diffusion_Fig2.png
```

`文档引用：` 后面的字符串就是返回表的最后一列。`writer-agent` 的规则是**逐字复制这一行**——它没有把 `figures/...` 改写成 `../analysis/figures/...` 的能力，也不该有这个负担。**漏写这一行，文档里就会缺图。**

### 4.5 取不到图是正常情况，不要反复重试

**工具只报告它找得到的图。** 一张图进入索引的条件是：它的图注就在它旁边（同栏、贴边），且这块区域能定位。取不到图有两种原因：

- **扫描版 PDF**：整页是一张位图，没有文字层，因而没有图注可配对；
- **该图注定取不到**：正文里写着「as shown in Fig. 3」但没有任何可定位的图像区域。

**不要换页码范围反复再试**——多试一次不会让图出现。按**降级写法**处理，在对应小节写一行：

```markdown
图见原文 Fig. 2（p.4）。
```

这条降级写法是**合规产出**，不是失败：它诚实说明了图在哪，读者可以打开 `papers/{论文短名}.pdf` 对应页查看。**绝不**为了"有图"而引用别处的图片。

> **为什么正文里的「Figure 3 shows…」不会变成一张图。** 这类句子也以「Figure 3」开头，但旁边没有图。工具会把它和真正的图注区分开——区分依据正是"旁边有没有图"——然后**丢掉**它，而不是从周围的空白里猜一个框。猜出来的框会把一整段正文裁下来、标成 Fig. 3 贴进文档，那比缺一张图更糟。所以：**索引里没有的图号，就是取不到**，写降级写法。
>
> 少数 PDF 使用了 JBIG2 / JPEG2000 压缩的位图，这些格式在当前环境的运行时 classpath 里没有解码器，渲染该页会失败，返回体如实报错——同样走降级写法。

## 5. 落盘：调用 `writePaperAnalysis`

四维信息与图片都准备好后，**必须落盘**——它是文档的事实来源，也是审查对象：

```
writePaperAnalysis(topic = {课题方向}, paperShortName = {论文短名},
                   sourceLevel = "FULL_TEXT",
                   oneLineSummary = {20-60 字的一句话定位},
                   content = {四维信息 Markdown})
```

参数要点：

| 参数 | 要求 |
|------|------|
| `topic` | 与输入给定的课题方向**逐字一致** |
| `paperShortName` | 与输入给定的短名**逐字一致**，也就是 PDF 的文件名（不含扩展名） |
| `sourceLevel` | **如实声明**你实际读到了多少，见 §3；虚标会让审查与用户都被误导 |
| `oneLineSummary` | 20-60 字，说明这篇做了什么、在本课题中的位置。它会出现在调研文档的论文清单里，**必须能独立看懂** |
| `content` | 四维信息的 Markdown 正文，标题从 `##` 开始（文件标题与元数据由工具生成） |

`content` 的结构：

```markdown
## 1. 论文概要与作者意图
{...}

## 2. 方法框架
{模块拆解与数据流；图号：Fig. 2（p.4）}
{![...](figures/...)}
{> 图注原文 / > 文档引用：...}

## 3. 关键机制与创新点
{公式原文 + 符号解释；必要时第二张图}

## 4. 训练目标
{损失函数、训练策略、与预训练目标的关系}

## 5. 可引用原句（供 blockquote）
- "{原文摘录 1}"
- "{原文摘录 2}"
```

工具会在文件开头自动写入 `# {论文短名}`、来源等级、一句话定位与生成时间。**重复调用同名论文会覆盖**——修订轮次重做精读时正是靠这个覆盖。图片覆盖同理：同一图号的图会被重新写入，不会留下碎片（图号取自图注，重跑不会改名、不会累积副本）。

## 6. 红线：这些事绝对不能做

1. **不得编造任何事实**：论文标题、作者、年份、会议名、公式、引用、实验数据、GitHub 链接，一律以原文为准。
2. **不得凭摘要推测公式**：公式必须来自 `extractPaperText` 读到的原文。摘要中的公式往往是简写，**不得据此补全**。
3. **不得超出来源等级**：`ABSTRACT_ONLY` / `SNIPPET` 的论文不展开方法细节、不写公式、不截图。
4. **图片路径只能逐字取自 `extractPaperFigures` 的返回表**。不得引用 skill 目录下的任何资源（尤其 `papper*.png`、`example/`、`template/`），不得引用其他论文目录下的文件，不得写绝对路径。也不得引用索引里没有的图号——那等于凭空写一个路径。
5. **不得漏写 `文档引用：` 行**：漏了文档就缺图，且 `writer-agent` 无从补。
6. **不得隐瞒信息缺口**：材料缺失的维度写 `[材料未提供]`，拿不到全文的写 `[仅摘要]`，公式不确定的写 `[公式待核对]`。
7. **只允许落盘到指定位置**：精读结果通过 `writePaperAnalysis` 写、图片通过 `extractPaperFigures` 写，路径固定为 `investigation/{课题方向}/analysis/` 与其下的 `figures/`。除此之外不写文件、不发邮件、不下载。
8. **不得写调研文档**：那是 `writer-agent` 的产物，你也没有这个工具。
9. **一次只做一篇**：只处理输入指定的这一篇论文，不要顺手去读、去截别的论文。
