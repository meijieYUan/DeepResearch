# 参考指南：调研文档撰写（`writer-agent`）

本文件是 `writer-agent` 的完整操作规程：输入契约、文档骨架、逐篇定位、对比分析、汇总表、排版与红线。

> **核心原则：写作是"翻译"而不是"创作"。**
> `research-agent` 交付的材料（候选池、判定表、下载清单、参考文献）与 `analyst-agent` 落盘的精读结果 `analysis/{论文短名}.md`，是仅有的两个事实来源。你负责把它们组织成结构清晰、可读性强的产出；你不负责补充材料中没有的信息。

> **你不碰 PDF。** 你**没有** `extractPaperText`，也没有 `extractPaperFigures`，无法自行翻阅或截图原文。需要某一篇更详细时走 `readPaperAnalysis`；怀疑某一篇的精读本身写错了，走 `reanalyzePaper`。这是刻意的边界：读懂一篇论文的代价（每篇最多 4 万字符）只付一次，付在 `analyst-agent` 那边。

> **文档只做归纳与对比，不复述四维正文。** 公式、符号解释、模块输入输出清单、训练细节都在 `analysis/` 里，文档用相对链接把读者送过去。抄回来会让文档体量重新随论文数膨胀——那正是旧版文档被模型输出上限中途截断的原因。

---

## 0. 产出位置

```
{项目根目录}/investigation/{课题方向}/
├── papers/{论文短名}.pdf                      # 只读，你不使用
├── analysis/{论文短名}.md                     # 你的输入：单篇精读结果
├── analysis/figures/{论文短名}_Fig{N}.png   # 你的输入：图片（只在文档里引用）
└── document/{文档名}.md                       # 你的产出
```

`{课题方向}` 必须与 `research-agent` 下载论文、`analyst-agent` 落盘精读时使用的课题方向**完全一致**，否则复用不到已下载的论文与已完成的分析。

保存调用：

```
writeResearchDocument(topic = {课题方向}, documentName = {文档名}, content = {完整 Markdown})
```

**`{文档名}` 由输入直接给定，每一轮都必须逐字使用同一个取值**，不得改名、加后缀或改动大小写。
工作流按固定文档名读取文档交给审查；一旦改名，磁盘上会留下多份文档，审查读到的仍是旧版本，修订等于白做。（多篇论文合写为一份文档，不要按论文拆成多个文件。）

## 1. 输入契约

撰写前确认手上具备：

| 输入 | 来源 | 必需性 | 缺失时的处置 |
|------|------|--------|-------------|
| 课题名称与范围 | 工作流传入 | 必需 | 向主 Agent 索取，不可自行编造 |
| 已下载论文清单与来源等级 | `research-agent` 的下载清单；或 `analyzePapers` 返回的索引 | 必需 | 用 `analyzePapers(topic)` 重新取得；来源等级缺失则按最低等级 `SNIPPET` 处理 |
| 论文短名 | 同上 | 必需 | 用于 `readPaperAnalysis` 的入参、清单行、相对链接，全篇必须一致 |
| **四维信息** | **`analysis/{论文短名}.md`**（由 `analyzePapers` 产出，用 `readPaperAnalysis` 读取） | 必需 | 某篇失败时按 `ABSTRACT_ONLY` 处理并在文档中标注；不得凭标题或印象补写 |
| **图片** | 各 analysis 文件里已嵌好的图与其 `> 文档引用：` 行 | 参考 | 没有图就照抄 analysis 里的「图见原文 Fig. N（p.X）」，**不得从别处找图补上** |
| 可引用原句列表 | 各 analysis 文件末尾的"可引用原句"一节 | 强烈建议 | 缺失则只做转述，不使用 blockquote 伪装引用 |
| 参考文献信息 | `research-agent` 的参考文献列表 | 必需 | 缺失字段写 `[信息缺失]`，**不得编造作者或会议名** |
| `template/template.md` | skill 目录 | 必需 | 文档结构的唯一权威 |
| `example/example.md` | skill 目录 | 参考 | 写作风格与详略程度的范例 |

**写作前必读 `template/template.md` 与 `example/example.md`**（用 `readSkillResource` 读取）。模板决定结构，范例决定粒度。

> **`example/example.md` 是风格范例，不是符合模板的完整交付物。** 它用于参考粒度与写法，**结构以 `template/template.md` 为准**；两者不一致时以模板为准。
>
> 范例里引用的 `papper*.png` 是**范例自带的素材**（与范例文件同目录），只用来演示"图放在哪、图注怎么写"。**你不得在自己的文档里引用它们**，也不得引用 skill 目录下的任何文件——正式文档的图只能来自 `analysis/figures/`。

**读取 analysis 文件的纪律**：**按需读取**，需要哪篇读哪篇。不要为了"读全"把所有论文一次性读进上下文——那会把这次分工省下的上下文压力重新加回来。

### 修订轮次

工作流可能带着上一轮审查的问题列表再次调用你，问题分两类，处理方式不同：

| `target` | 含义 | 你的动作 |
|----------|------|---------|
| `ANALYST` | 某篇的**精读结果本身有误**（公式与原文不符、来源等级标错、维度缺失、图片引用写错） | 先 `reanalyzePaper(topic, 论文短名, reason)` 重做该篇精读，再 `readPaperAnalysis` 读回重做后的结果，更新文档中受影响的对比结论与图片引用 |
| `WRITER` | **文档自身的问题** | 直接修订文档 |

1. **只针对列出的问题修订**，不要推倒重写整个文档。
2. 修订后**重新调用 `writeResearchDocument` 覆盖保存同一文档名**（同一课题方向 + 输入给定的同一文档名，逐字一致）。
   改名会让审查读到旧版本，这是修订轮次最常见的失败原因。
3. **不要自己改写 analysis 文件**——你也没有这个能力。分析有误只能通过 `reanalyzePaper` 重做。
4. 若问题列表为空但文档仍被判不通过，说明审查输出异常——按 §9 完整自检一遍再提交。

## 2. 文档骨架

严格遵循 `template/template.md`：

```
[TOC]

# {课题标题}

> **调研背景**: {简要说明调研背景和目的}
> **调研范围**: {时间范围}，入选论文 {N} 篇（FULL_TEXT {a} 篇，仅摘要来源 {b} 篇）

**关于详细内容**：{说明四维信息在 analysis/ 目录，本文档只做归纳与对比}

## 论文清单
| # | 论文 | 年份/会议 | 来源等级 | 一句话定位 | 详细分析 |

# 1. 逐篇定位
## 1.1 {论文短名一}      （2-4 句 + 至多 2 张图）
## 1.2 {论文短名二}

# 2. 对比分析
## 2.1 方法框架对比
## 2.2 关键机制对比
## 2.3 训练目标对比
## 2.4 对比汇总表

# 3. 结论与开放问题

# 参考文献
```

### 结构硬性规则

| 规则 | 说明 |
|------|------|
| 目录标记 | 固定写 `[TOC]`（大写），模板与审查都按这个写法核对 |
| 标题层级 | 课题标题用 `#`；`# 1.` / `# 2.` / `# 3.` 为一级章节；`## x.y` 为二级小节 |
| 论文清单 | 位于调研背景之后、正文之前，**六列齐全**，末列是相对链接 |
| 逐篇定位 | 每篇 2-4 句，**不复述四维正文**；按"方法演进逻辑"或"时间顺序"排列 |
| 对比分析 | 文档的核心价值所在，按维度横向组织，**以表格为主** |
| 汇总表位置 | 位于对比分析末节、结论之前 |
| 分隔线 | 主要章节之间用 `---` 分隔 |

**不要增删章节**。某篇论文的某个方面确实不适用时，在对比表中写明"不适用"及其原因，而不是删掉行——删行会破坏文档的可对比性。

## 3. 逐篇定位的写法

这一节替代了旧版"每篇论文写全四维"的写法。**每篇只写 2-4 句**，回答三个问题：

1. 这篇论文**解决什么问题**？
2. 它的**核心手段**是什么（一句话）？
3. 它在**本课题中处于什么位置**——是开创性的、改进型的，还是对某类方法的批判？

```markdown
## 1.1 MS-Diffusion

针对多主体个性化中常见的 subject neglect 与身份混合，MS-Diffusion 把 bbox 约束引入
image cross-attention，让每个主体的视觉特征主要作用于指定区域。它是本课题中"以显式空间
约束换取身份保真"这一路线的代表，代价是推理时需要用户提供 bbox。

![MS-Diffusion 方法框架](../analysis/figures/MS-Diffusion_Fig2.png)

> 图注原文：Fig. 2 Overview of MS-Diffusion.
```

**不要写的**：模块的输入输出清单、公式、符号解释、训练细节——那些在 `analysis/{短名}.md` 里，清单行的链接会把读者送过去。**文档里重复一遍，正是这次重构要消除的东西。**

### 3.1 图片怎么放（只有一种正确来源）

- **来源**：`analysis/{短名}.md` 里 `analyst-agent` 已经嵌好的图。你能看到的每张图下面都有一行
  `> 文档引用：../analysis/figures/{短名}_Fig{N}.png`。
- **动作**：把那一行的路径**逐字复制**进下面的图片语法里，其余一个字都不要改：

```markdown
![{论文短名} 方法框架](../analysis/figures/{论文短名}_Fig{N}.png)

> 图注原文：Fig. {n} {图注}
```

- **不要**自己拼路径、不要改前缀（`../analysis/` 一个字符都不能少也不能多）、不要改文件名、不要写绝对路径。
- **张数**：每篇至多 2 张——1 张方法框架图放在该篇的逐篇定位里，必要时再放 1 张关键机制图。这一上限与 `analyst-agent` 的截图上限一致。
- **该篇没有图**：analysis 里已写好「图见原文 Fig. N（p.X）」，照抄这一行即可，并**删掉**图片行。
  **绝不**用别的论文的图、范例的图或任何 skill 目录下的文件来"补上"——那是凭空引用，审查会判 BLOCKER。

## 4. 对比分析的写法（本文档的核心）

逐篇定位是"分别介绍"，对比分析才是本文档存在的理由：把几篇论文**放在同一把尺子下**比较。

**三条纪律**：

1. **按维度横向组织，不要按论文逐个展开。** 一个好用的检验：把某一段单独拿出来，如果它只讲了一篇论文，那它属于 §3 而不属于这里。
2. **以表格为主。** 表格天然迫使你横向对齐，也让差异一眼可见；纯文字段落容易退化成各说各话。
3. **不要逐对枚举。** 有 N 篇论文时不要写 "A 与 B 的差异…""A 与 C 的差异…"——那会产生 N² 量级的内容，文档体量会失控（这正是旧版文档被模型输出上限截断的原因）。按维度组织只需 N 列。

### 4.1 方法框架对比

横向比较各论文的**模块划分与数据流**差异。

| 对比维度 | MS-Diffusion | {论文二} | {论文三} |
| -------- | ------------ | -------- | -------- |
| 模块划分 | Grounding Resampler + Multi-subject Cross Attention | {…} | {…} |
| 数据流 | 特征先经 resampler 汇聚，再以 bbox mask 约束 attention | {…} | {…} |
| 空间约束来源 | 用户给定 bbox | {…} | {…} |

### 4.2 关键机制对比

比较**核心机制的差异、各自解决什么、适用场景有何不同**。关键符号可以引用，**完整公式不在此重复**——需要时注明"公式见 `analysis/{短名}.md`"。**也不在此重复插图**：图属于逐篇定位，同一张图在文档里出现两次是冗余。

要写出**取舍**：某个机制更强，通常是以什么为代价（推理开销、需要额外输入、泛化性、训练成本）。

### 4.3 训练目标对比

比较**训练目标与训练策略**的差异：是否训练、训练什么、分几阶段、沿用还是修改了预训练目标。

training-free 的方法在此**明确写出"无新增训练目标"**，并说明它靠什么替代训练。同一篇论文的推理期约束与训练目标必须区分开，不要混为一栏。

### 4.4 对比汇总表

见 §5。

## 5. 汇总表

汇总表是全文的"一页速览"，**必须包含且仅包含以下五列**：

| 论文 | 作者主要想解决的问题 | 方法框架 | 关键机制 | 是否 Training-free |
| ---- | -------------------- | -------- | -------- | ------------------ |

**填写要求**：

| 列 | 要求 |
|----|------|
| 论文 | 使用**论文短名**，与逐篇定位的小节标题保持一致 |
| 作者主要想解决的问题 | 一句话，**不超过 25 字**，用作者视角表述 |
| 方法框架 | 模块名串联，用 `+` 连接（如 `Grounding Resampler + Multi-subject Cross Attention`） |
| 关键机制 | 一句话点明核心手段（如 `用 bbox mask 限制每个 subject attention 的空间作用范围`） |
| 是否 Training-free | `是` / `否`；若为部分场景 training-free，写 `否，推理使用较灵活` 这类明确表述，不要含糊 |

**对比性要求**：每一列都应该让读者能横向对比。若两篇论文在某列的表述几乎相同，说明该列没有提炼出差异，需要重写。

## 6. 参考文献

- 编号与论文清单的行号**一致**（清单第 1 行 → 文献 1）
- 完整引用信息：**作者、标题、会议/期刊全称、年份、链接**
- 信息以 `research-agent` 材料为准；材料中缺失的字段写 `[信息缺失]`，**不得编造作者或会议名**
- 来源为 `ABSTRACT_ONLY` / `SNIPPET` 的论文，在条目末尾标注来源等级

---

## 7. 语言与排版规范

| 维度 | 规范 |
|------|------|
| 语言 | **中文为主**，专业术语保留英文（如 grounding token、cross-attention、bbox） |
| 风格 | 学术化但可读性强；避免口语化，也避免堆砌术语 |
| 术语一致性 | 同一概念全篇用同一译法/写法；论文短名、模块名、符号**全篇统一** |
| 加粗 | 用于**术语首次出现**和**关键结论**，不用于整句强调 |
| blockquote | 只用于**作者核心意图**与**机制有效性总结**两类内容，不滥用；文档中尤其少用（四维正文里的 blockquote 留在 analysis 文件里） |
| 列表 | 并列关系用无序列表；有顺序的流程用有序列表 |
| 表格 | 对比分析以表格为主；表格列数 = 论文数 + 1（对比维度列） |
| 分隔 | 主要章节之间用 `---` |
| 空行 | 标题、公式块、图片、列表、blockquote 前后保留空行（Markdown 渲染需要） |
| 目录 | 固定 `[TOC]` |
| 图片 | 路径逐字来自 analysis 的 `> 文档引用：` 行；图注在图片**下方**并标注原文图号；每篇至多 2 张 |

## 8. 红线：这些事绝对不能做

1. **不得编造任何事实**：论文标题、作者、年份、会议名、公式、引用、实验数据、GitHub 链接，一律以材料或 analysis 文件为准。
2. **不得虚构引用**：blockquote 中的内容必须是论文原文或材料提供的原句；没有原句就改为普通转述。
3. **不得超出来源等级**：`ABSTRACT_ONLY` 的论文不展开方法细节、不写公式；`SNIPPET` 的论文只作背景铺垫。
4. **不得在文档中复述四维正文**：每篇 2-4 句定位 + 相对链接，公式与细节留在 `analysis/`。抄回来会让文档体量重新随论文数膨胀。
5. **不得凭空引用图片**：图片路径只能逐字取自 analysis 文件里的 `> 文档引用：` 行。不得引用 skill 目录下的任何资源（`papper*.png`、`example/`、`template/`），不得引用别的论文的图，不得写绝对路径。没图就写「图见原文 Fig. N（p.X）」。
6. **不得隐瞒信息缺口**：材料缺失的维度写 `[材料未提供]`，拿不到全文的写 `[仅摘要]`，公式不确定的写 `[公式待核对]`。
7. **只允许落盘到指定位置**：文档通过 `writeResearchDocument` 写，路径固定为 `investigation/{课题方向}/document/{文档名}.md`。除此之外不写文件、不发邮件、不下载。
8. **不得改变模板结构**：模板是文档结构的唯一权威，不增删章节层级、不调整章节顺序。
9. **不得越权下载或读 PDF**：你没有下载工具，也没有读取 PDF 与截图的工具。论文不够或不合格时，如实说明并由工作流回退到检索阶段（`target=RESEARCHER`），不要试图自行获取。
10. **不得改写他人的产物**：不得直接改写 `analysis/` 下的文件或其中的图片引用（也没有这个能力）；分析有误只能通过 `reanalyzePaper` 重做。
