# ResearchAgent 参考指南：检索、相关性判定与下载

本文件是 `research-agent` 执行"第二步 检索与相关性判定"时的完整操作规程。

> **核心原则：下载是昂贵且不可逆的（占用磁盘、消耗上下文），因此下载必须发生在摘要级相关性判定通过之后。**
> 先建候选池 → 再判定 → 最后只下载判定为"相关"的论文。

> **你的职责到下载为止。** 精读论文正文、提取方法框架/公式/训练目标、以及从 PDF 里截取该论文的图，都是 `analyst-agent` 的工作（见 `references/analysis-guide.md`）；它由写作阶段逐篇触发，把结果落盘到 `analysis/`。
> 你**没有**读取 PDF 正文的工具——这是有意为之，不要试图用 `webCrawl` 绕过。
> 你的交付物是：**候选池 + 相关性判定表 + 下载清单 + 参考文献**（见 §7 输出契约）。

---

## 0. 工具能力边界（先读这一节，它决定所有策略）

必须先清楚手上工具的真实能力，否则会写出无效的检索计划：

| 工具 | 实际行为 | 关键限制 |
|------|---------|---------|
| `webSearch` | Bing 检索（cn.bing.com），返回**最多 8 条**结果的标题 + 摘要片段 + URL | 只返回 8 条，因此**必须靠多组检索式扩大候选池**，不能指望一次搜索拿到全部候选 |
| `webCrawl` | 抓取 URL 并抽取正文纯文本 | **只处理 HTML**，返回内容**超过 8000 字符会被截断**；**无法解析 PDF 二进制** |
| `downloadPaper` | 下载论文 PDF 到 `investigation/{课题方向}/papers/`，自动重试、校验、去重 | 接受 PDF 链接 / arXiv abs 页 / DOI / 出版社 landing page；**仅用于已判定相关的论文** |
| `listDownloadedPapers` | 列出某课题下已下载的论文（大小、页数） | 下载前先查，避免重复下载 |

> 读取 PDF 正文与从 PDF 截图的能力都属于 `analyst-agent`——精读与取图是为写作准备素材的环节，不属于检索。不要尝试用 `webCrawl` 打开 `.pdf` 链接来代劳（它只解析 HTML，对 PDF 只会返回乱码或空内容）。

由此推出三条硬性结论：

1. **候选池靠"多检索式 × 多站点"堆出来**，而不是靠单次搜索。
2. **摘要必须从论文的 HTML 摘要页读取**（arXiv `/abs/` 页、Semantic Scholar 论文页、PubMed 页、出版社 landing page 等），**不要试图用 `webCrawl` 打开 `.pdf` 链接**——那只会拿到乱码或空内容。
3. **`downloadPaper` 是唯一的副作用操作**，且只对通过 §5 判定的论文调用；其余一律只读。

**降级链（所有抓取动作都适用）**：

```
论文 HTML 摘要页  →  会议/期刊 landing page  →  聚合站页面（Semantic Scholar / DBLP / OpenReview）
   →  搜索结果里的摘要片段  →  标记 SOURCE_LEVEL=SNIPPET 并显式记录
```

任何一级成功即停止下降。走到底仍拿不到摘要时，**标记为 `UNKNOWN` 且不下载**，在材料中如实记录。

## 1. 输入解析

从主 Agent 传来的课题描述中解析出以下字段，缺失则用默认值并记录：

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `topic` | 必填 | 课题的精确描述 |
| `year_from` / `year_to` | 近 3-5 年 | 发表年份区间 |
| `target_count` | 4-8 | 最终需要精读的论文数 |
| `languages` | 中英文均可 | 中文课题必须中英文都检索 |

**候选池规模**：`candidate_pool = target_count × 3`（目标 6 篇 → 候选约 18 篇）。候选池不足目标数的 2 倍时，必须追加检索式或放宽检索条件后再判定，**不允许在候选池过小的情况下直接开始判定**。

---

## 2. 构造检索式

### 2.1 关键词提取

从课题中提取 **2-4 组**中英文核心关键词组合，每组包含：

- **核心概念词**：课题的主体对象（如 `multi-subject image generation`）
- **限定词 / 方法词**：约束研究角度（如 `layout control`、`personalization`、`diffusion`）
- **同义词与缩写**：同义表达、领域惯用缩写（如 `T2I`、`text-to-image`、`personalized diffusion`）

中文课题额外提取中文关键词用于 CNKI 检索。

### 2.2 检索式模板

```
# 精确式（先跑，命中少但准）
"<核心概念词>" "<限定词>"

# 宽式（补候选池用）
<核心概念词> <限定词> (survey OR review)

# 站点限定式
site:arxiv.org <核心概念词> <限定词>
site:openreview.net <核心概念词> <限定词>

# 时间限定式（Bing 语法）
<核心概念词> <限定词> after:2022-01-01
```

**每篇论文的检索至少覆盖 3 组不同检索式**，避免单一措辞造成的系统性漏检。

### 2.3 检索站点矩阵（按推荐优先级）

| 优先级 | 站点 | 适用领域 | 检索策略 | 摘要可读性 |
|-------|------|---------|---------|-----------|
| 1 | [arXiv](https://arxiv.org) | CS、数学、物理 | `/list` 或 `site:` 检索，按 relevance 排序，关注近 3 年 | 高（`/abs/` 页有完整摘要） |
| 2 | [Semantic Scholar](https://semanticscholar.org) | 全学科 | 关键词检索 + 按引用量筛选 | 高（页面含 TL;DR 与摘要） |
| 3 | [OpenReview](https://openreview.net) | ML 顶会 | 按会议检索，可读到评审意见 | 高 |
| 4 | [DBLP](https://dblp.org) | 计算机科学 | 按会议/期刊定位顶会论文 | 低（仅题录，需跳转） |
| 5 | [Google Scholar](https://scholar.google.com) | 全学科 | 按引用量排序 | 中（可能被反爬拦截） |
| 6 | [中国知网 CNKI](https://cnki.net) | 中文学术 | 中文课题必查 | 中（摘要页可读） |
| 7 | [PubMed](https://pubmed.ncbi.nlm.nih.gov) | 生物医学 | 生命科学课题 | 高 |
| 8 | [IEEE Xplore](https://ieeexplore.ieee.org) | 电子工程、CS | 工程类课题 | 中（landing page 有摘要） |

**至少检索 3 个站点**，其中 arXiv 或 Semantic Scholar 必查（CS 类课题）。中文课题必须包含 CNKI。

## 3. 建立候选池

对每条搜索结果记录一条候选条目：

```markdown
### C{序号}
- **标题**: {完整标题}
- **年份**: {年份}
- **来源**: {会议/期刊/arXiv 编号}
- **URL**: {链接}
- **摘要片段**: {搜索结果中给出的摘要片段原文，若无则写 NONE}
- **发现于**: {检索式 / 站点}
- **初步印象**: {待判定}
```

**去重规则**（在候选池阶段就要做）：

- 同一论文的 arXiv 版与会议版 → 合并为一条，保留**会议版**信息、记录 arXiv 链接备用
- 标题归一化后（小写、去标点、去空格）相似度极高 → 视为同一篇
- 同一论文的 extended / workshop 版本 → 保留信息量最大的版本，在备注中注明存在其他版本

**覆盖度检查**（候选池成型后自检）：

- [ ] 是否覆盖不同方法流派？（如 training-based vs training-free）
- [ ] 是否覆盖不同年份？（不要全部集中在同一年）
- [ ] 是否覆盖不同团队/机构？（避免同一课题组的系列论文）
- [ ] 是否有综述类论文作为领域地图？（可选，但很有用）

## 4. 轻量初筛（仍然不下载）

在正式判定前，用**成本最低**的信息淘汰明显无关的候选：

| 淘汰信号 | 说明 |
|---------|------|
| 年份超范围 | 早于 `year_from` 且无特殊理由 |
| 非研究论文 | 社论、新闻、产品介绍、纯 demo 页面 |
| 标题明显跨领域 | 关键词表面命中但领域完全不同（见 §5.3 假阳性） |
| 标题重复已入选论文 | 同质化严重，除非有独特视角 |

初筛只淘汰**明显**无关项，边界情况一律留到 §5 判定，不要在此阶段过度淘汰。

---

## 5. 摘要级相关性判定（下载的唯一闸门）

### 5.1 判定流程

对每个通过初筛的候选：

1. **获取摘要**：按 §0 的降级链读取论文 HTML 摘要页。**标题不足以判定，必须读到摘要正文。**
2. **逐维打分**：按 §5.2 的五维评分表打分。
3. **摘录证据**：**必须从摘要原文中摘录一段支撑判定的原句**（英文原句照抄，不翻译、不改写）。
4. **给出结论**：按 §5.4 阈值判定 `RELEVANT` / `BORDERLINE` / `IRRELEVANT`。
5. **记录输出**：按 §5.5 格式写入判定表。

### 5.2 五维评分表

每维 0-5 分，加权后满分 100。

| 维度 | 权重 | 5 分（完全符合） | 3 分（部分符合） | 0 分（不符合） |
|------|------|----------------|----------------|--------------|
| **A. 主题匹配** | 35% | 研究对象与课题完全一致 | 同一大领域但具体对象不同 | 不同领域 |
| **B. 问题匹配** | 25% | 解决的核心问题正是课题关注的问题 | 问题相关但侧重不同 | 问题无关 |
| **C. 方法相关性** | 15% | 方法思路对课题有直接借鉴价值 | 方法可迁移但需改造 | 方法无参考价值 |
| **D. 时效性** | 15% | 在 `[year_from, year_to]` 内 | 略超出但在合理外延内 | 明显过时 |
| **E. 论文质量** | 10% | 顶会/顶刊、高引用、有开源代码 | 正规发表、引用一般 | 来源不明、非同行评议 |

**加权得分** = `A×0.35 + B×0.25 + C×0.15 + D×0.15 + E×0.10`，再乘 20 折算为百分制。

> **注意 C 维度的用意**：它衡量的是"方法对课题是否有借鉴价值"，**不是"方法是否和已入选论文相同"**。相反，方法流派重复的论文应主动降权，以保证 §3 的覆盖度要求。

### 5.3 假阳性识别（必须逐条排查）

以下情况是关键词检索的典型陷阱，命中时**直接判 `IRRELEVANT`**，无论表面关键词多吻合：

| 陷阱 | 例子 |
|------|------|
| **同词不同域** | 课题关注图像生成的 `layout`，候选是 PCB 版图布局 / 数据库 layout / 排版 layout |
| **同域不同任务** | 课题关注 `multi-subject` 生成，候选是 `multi-object tracking` |
| **方法名撞车** | 缩写相同但全称完全不同 |
| **综述错配** | 候选是另一个领域的综述，只是标题含相同术语 |
| **仅引用关系** | 候选只是"被课题相关论文引用"，本身不研究该问题 |

### 5.4 判定阈值

| 得分 | 判定 | 处置 |
|------|------|------|
| **≥ 65** | `RELEVANT` | 进入下载队列 |
| **50 - 64** | `BORDERLINE` | 先不下载；下载队列不足目标数时，按得分从高到低补入，并在材料中标注 `[边界相关]` |
| **< 50** | `IRRELEVANT` | 放弃，仅在候选池记录中保留判定理由（便于后续追溯为何排除） |

**额外约束**：

- `RELEVANT` 条目中，若 **A 维（主题匹配）< 4 分**，则强制降为 `BORDERLINE`——主题不吻合的高分论文往往是方法可借鉴但对象不对，不应占用精读名额。
- 若判定为 `RELEVANT` 的论文数**超过** `target_count`，按加权得分排序，同时保证 §3 的覆盖度要求，择优选取。
- 若判定为 `RELEVANT` 的论文数**不足** `target_count` 的一半，说明检索式覆盖不足，**回到 §2 追加检索式重新建池**，而不是降低阈值硬凑。

### 5.5 判定输出格式

```markdown
## 相关性判定表

| 编号 | 论文标题 | A | B | C | D | E | 加权分 | 判定 | 摘要证据（原文摘录） |
|------|---------|---|---|---|---|---|--------|------|---------------------|
| C1 | {标题} | 5 | 5 | 4 | 5 | 5 | 96 | RELEVANT | "..." |
| C2 | {标题} | 3 | 2 | 3 | 4 | 4 | 60 | BORDERLINE | "..." |
| C3 | {标题} | 1 | 0 | 2 | 3 | 3 | 27 | IRRELEVANT | "..." |

### 排除说明
- **C3**：标题含 "layout"，但摘要表明研究对象是 PCB 版图布线，与图像生成无关。（同词不同域）
```

**判定表的每一行都必须有摘要证据摘录。没有证据摘录的判定视为无效判定，不得据此下载。**

## 6. 下载与保存

### 6.1 下载前置检查

下载前逐条确认：

- [ ] 该论文在 §5.5 判定表中为 `RELEVANT`（或经 §5.4 补入的 `BORDERLINE`）
- [ ] 判定行包含摘要原文证据摘录
- [ ] 已确认这是该论文的正确版本（会议版优先，arXiv 版备用）
- [ ] 目标路径与文件名已按 §6.2 规范确定，且不与已有文件冲突

### 6.2 命名与目录规范

所有产出按**课题方向**归档在项目根目录下：

```
{项目根目录}/
└── investigation/
    └── {课题方向}/                    # 本次调研的课题方向
        ├── papers/                    # 论文原件（你负责的一层）
        │   └── {论文短名}.pdf
        ├── analysis/                  # 逐篇精读结果（analyst-agent 产出）
        │   └── {论文短名}.md
        └── document/                  # 调研文档（writer-agent 产出）
            └── {文档名}.md
```

**课题方向（topic）是目录的唯一键**：

- 你手上的两个论文工具（`downloadPaper` / `listDownloadedPapers`）都必须传入课题方向。后续的精读与写作阶段用同一个课题方向读取论文、落盘分析与文档。
- 同一次调研中，**所有工具调用的课题方向必须完全相同**，否则论文和文档会被拆到不同目录。
- 课题方向**不区分对话（thread）**：换一个对话继续调研同一课题，只要课题方向一致，就能直接复用已下载的论文。这正是 `listDownloadedPapers` 查重的意义。
- 取值应稳定、简洁，直接用课题名称即可（如 `多主体布局控制`）；工具会自动做安全处理。

- **论文短名**：优先用论文的通用缩写（如 `MS-Diffusion`、`AnyMS`）；无通用缩写时用标题首字母缩写 + 年份（如 `LCPD2024`）。
- 短名一旦确定，在**全文所有位置保持一致**（PDF 文件名、精读文件名、文档清单与汇总表）。`analyst-agent` 按短名找到 PDF，`writer-agent` 按短名读取精读结果、也让读者用短名找到对应文件——短名不一致会导致整条链断开。图也会跟着短名走（`analysis/figures/{论文短名}_Fig{N}.png`），短名不一致同样会让图找不到归属。
- **不下载图片**：你的工具只处理 PDF，也没有把图落盘的能力。原文中的框架图由 `analyst-agent` 用 `extractPaperFigures` **从 PDF 里直接截取**（不需要你去找图片 URL），再由精读结果与调研文档各自引用。你既不用下载图片，也不要在下载清单里记录图片链接。

### 6.3 下载执行

**先查重**：调用 `listDownloadedPapers(topic = {课题方向})`，看该课题下是否已下载过，避免重复抓取。

**再下载**：对每篇判定通过的论文调用一次

```
downloadPaper(topic = {课题方向}, url = {PDF 链接 / arXiv abs 页 / DOI 页}, shortName = {论文短名})
```

保存路径为 `investigation/{课题方向}/papers/{论文短名}.pdf`，返回值中的 `path` 即实际路径。

`downloadPaper` 已内建以下保障，**不需要你手动重试或校验**：

| 保障 | 说明 |
|------|------|
| 自动重试 | 传输错误与 408/425/429/5xx 会按指数退避 + 抖动重试，并遵守 `Retry-After` |
| 落地页解析 | 传入 arXiv abs 页 / DOI / 出版社页面时，自动定位真正的 PDF 链接 |
| 真实性校验 | 校验 `%PDF-` 魔数与 PDFBox 可解析性，避免把 HTML 错误页存成 PDF |
| 去重 | **按解析后的文件名判重**：目标文件已存在且可解析时，重复调用会跳过而非重下。因此短名就是去重键——**同一篇论文换了短名会被重新下载**。 |
| 路径安全 | 课题方向与短名中的分隔符、`..` 会被清理，文件始终落在该课题的 `papers/` 内 |

**下载完成后你的工作即结束**：不要读取正文（你没有这个工具）。把短名与来源等级写进 §7 输出契约，交给 `analyst-agent` 去精读。

**下载失败处理**：`downloadPaper` 返回 `DOWNLOAD_FAILED` 时，它会列出每次尝试的失败原因，据此决策：

| 失败原因 | 处置 |
|---------|------|
| 404 / 链接失效 | 换 arXiv 版、OpenReview 版或作者主页 |
| 403（bot 防护） | 换镜像站或聚合站；`host-fallbacks` 可配置镜像 |
| 超时 / 连接错误 | 已自动重试；仍失败则换源 |
| 无 PDF 链接（付费墙） | 降级为 `SOURCE_LEVEL=ABSTRACT_ONLY` 并显式标注 |

**仍然失败时**，输出下载清单交由主 Agent 处理：

```markdown
## 下载清单

| 序号 | 论文短名 | 判定得分 | PDF URL | 目标路径 | 备用 URL |
|------|---------|---------|---------|---------|---------|
| 1 | MS-Diffusion | 96 | https://arxiv.org/pdf/xxxx | investigation/{课题方向}/papers/MS-Diffusion.pdf | https://... |
```

**不允许对同一 URL 无意义重试**——`downloadPaper` 内部已重试过，你的职责是换源，不是再调一次。

### 6.4 来源等级标注

每篇论文必须标注来源等级，供 `analyst-agent` 判断能写多深、供 `writer-agent` 与 `reviewer-agent` 核对可信度：

| 等级 | 含义 | 可用信息 |
|------|------|---------|
| `FULL_TEXT` | 已获取全文 | 全部四维信息，公式可逐字核对 |
| `ABSTRACT_ONLY` | 仅摘要页 | 概要与意图可靠；**方法细节与公式不得展开** |
| `SNIPPET` | 仅搜索结果片段 | 仅可用于背景铺垫，**不得作为论据** |

**`ABSTRACT_ONLY` 与 `SNIPPET` 的论文，其公式一律不得写入精读结果，也不得写入文档。** 这是防止编造公式的第一道防线。

---

## 7. 输出契约（交给后续阶段的材料）

你的产出必须包含以下四部分，缺一不可。`analyst-agent` 靠短名与来源等级决定逐篇精读时能写多深，`writer-agent` 靠清单与参考文献成文。

### 7.1 候选池

按 §3 格式记录的完整候选列表（含被排除项）。这是"为什么最终选了这几篇"的追溯依据。

### 7.2 相关性判定表

按 §5.5 格式的判定表，**每行必须带摘要原文证据摘录**。没有证据的判定视为无效判定。

### 7.3 下载清单

按 §6.3 格式的下载清单，每篇必须标明：

```markdown
## 下载清单

| 序号 | 论文短名 | 判定得分 | 来源等级 | 目标路径 | 备用 URL |
|------|---------|---------|---------|---------|---------|
| 1 | MS-Diffusion | 96 | FULL_TEXT | investigation/{课题方向}/papers/MS-Diffusion.pdf | https://... |
```

**`来源等级` 是你必须逐篇给出的字段**，它直接决定下游能写多深：

| 等级 | 含义 | 下游可用的信息 |
|------|------|------------------------|
| `FULL_TEXT` | PDF 已成功下载且可解析 | 可精读正文、四维信息完整、公式可逐字核对 |
| `ABSTRACT_ONLY` | 仅有摘要页 | 仅概要与意图可靠；**不得展开方法细节与公式** |
| `SNIPPET` | 仅搜索结果片段 | 仅可作背景铺垫，**不得作为论据** |
| `UNKNOWN` | 摘要也拿不到 | **不下载**，仅记录 |

> 你不需要判断 PDF 正文能否解析——`downloadPaper` 已做真实性校验，下载成功即 `FULL_TEXT`；它明确失败并降级时按降级等级标注。

### 7.4 参考文献

每篇入选论文给出完整引用信息：**作者、标题、会议/期刊全称、年份、链接**。

- 信息从摘要页/landing page 读取，**不得编造作者或会议名**
- 确实读不到的字段写 `[信息缺失]`，由 `writer-agent` 原样保留
- 条目末尾标注来源等级

## 8. 失败模式与处置速查

| 现象 | 原因 | 处置 |
|------|------|------|
| 搜索结果只有 8 条 | `webSearch` 的固有上限 | 换检索式、换站点，多次检索堆候选池 |
| `webCrawl` 打开 PDF 返回乱码/空 | 工具只解析 HTML | 改抓 `/abs/` 摘要页；下载改用 `downloadPaper` |
| 摘要页正文被截断（>8000 字符） | 工具截断 | 摘要在页面开头，通常不受影响；若被截，改用 Semantic Scholar 页 |
| Google Scholar 被拦截 | 反爬 | 改用 arXiv / Semantic Scholar / OpenReview |
| 某篇论文找不到 HTML 摘要页 | 闭源期刊 | 走降级链，最终标 `SNIPPET` 或 `UNKNOWN` |
| 判定为 RELEVANT 的数量不足 | 检索式覆盖不足 | **回到 §2 追加检索式**，不降低阈值 |
| 候选池全是同一方法流派 | 检索式偏斜 | 追加对立流派的检索词（如加 `training-free`） |
| `downloadPaper` 返回 403 | bot 防护 | 换镜像站 / 聚合站；可在 `agent.paper.host-fallbacks` 配置镜像 |
| `downloadPaper` 返回"不是可解析 PDF" | 拿到的是错误页 | 换源；不要重复调用同一 URL |
| `downloadPaper` 提示已下载 | 目标文件名已存在 | 确认是同一篇论文即复用；**若是不同论文，换一个短名** |
| 全文拿不到但论文很关键 | 闭源 | 标 `ABSTRACT_ONLY`，显式标注，只写概要级信息 |

> 检索阶段的失败**不要靠重试解决**，靠换源、换检索式、换站点。同一 URL 或同一检索式失败两次即改变策略。

## 9. 执行自检清单

交付材料前逐项确认：

- [ ] 候选池规模 ≥ `target_count × 2`（理想为 ×3）
- [ ] 至少检索了 3 个站点，中文课题含 CNKI
- [ ] 每篇入选论文都有摘要原文证据摘录
- [ ] 判定表完整，包含被排除论文及排除理由
- [ ] `downloadPaper` 仅针对判定通过的论文调用，且下载前已用 `listDownloadedPapers` 查重
- [ ] 所有工具调用使用了**同一个**课题方向取值，论文均落在 `investigation/{课题方向}/papers/` 下
- [ ] 所有文件名与短名规范一致，无冲突
- [ ] 下载清单中每篇都标注了**来源等级**

- [ ] **未尝试读取任何 PDF 正文**（那是 analyst-agent 的工作）
- [ ] 未执行任何写入/删除/邮件等副作用操作（除约定的下载外）
