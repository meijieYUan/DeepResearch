# ReviewerAgent 参考指南：调研文档与精读结果质量检查

本文件是 `reviewer-agent` 执行"第五步 质量检查"时的完整操作规程。你的结构化结论是工作流决定是否继续修订、以及回退到哪一步的唯一依据。

> **核心原则：审查的基准是"论文原文与材料"，不是"你的知识"。**
> 你要检查的是"产出是否忠实、完整、规范地反映了论文原文（用 `extractPaperText` 读取）、`research-agent` 交付的材料与 SKILL.md 的规范"。
> **不要用你自己的领域知识去"纠正"产出内容**——你的知识可能过时或有误，用它去改一份有原文依据的产出，会把正确的内容改错。发现疑点时，正确做法是**标记为"需人工核对"并指出核对方法**，而不是直接判定错误。

---

## 0. 审查两个对象（先读这一节）

产出分成两份，**两份都要审**：

| 对象 | 位置 | 承载什么 | 漏审的后果 |
|------|------|---------|-----------|
| **精读结果** | `investigation/{课题方向}/analysis/{论文短名}.md`，一篇一个文件 | **四维信息全文、公式逐字抄录**、来源等级 | 公式与细节现在只活在这里，不审它等于**放弃了事实核对** |
| **调研文档** | `investigation/{课题方向}/document/{文档名}.md` | 论文清单、逐篇定位、跨论文对比、汇总表、参考文献 | 对比结论可能没有分析依据 |

**分工决定了审查重点**：文档**不复述**四维正文，所以「公式对不对」「四维齐不齐」要在 **analysis 文件**里查；文档要查的是「对比结论有没有分析依据」「有没有越界把四维抄回来」「结构与模板是否一致」。**不要把本该在 analysis 里查的检查项拿去判文档不通过**——那是判错了对象，会让 writer 去做它做不到的修改。

工作流会在输入中给出 `analysis/` 的清单（短名 / 来源等级 / 相对路径）。**正文由你自己用 `readPaperAnalysis(topic, 论文短名)` 按需读取**，不要把 N 份正文一次性读进来——按 §6 的顺序，先做便宜的结构检查，被结构问题挡住的篇目就不必再读它的正文了。

## 1. 审查输入

| 输入 | 来源 | 用途 |
|------|------|------|
| 待审调研文档 | 工作流传入 | 审查对象一 |
| **`analysis/` 清单与精读文件** | 工作流传入的清单；正文用 `readPaperAnalysis(topic, 短名)` 按需读 | **审查对象二**；也是文档对比结论的**事实依据** |
| **已截取的图片清单** | 工作流传入（逐张列出实际存在的文件） | 核对文档与 analysis 里每个 `![..](..)` 是否指向真实文件，见 §2.8 的 P2/P3 |
| 论文原文 | `extractPaperText(topic, pathOrName)` | **事实基准**：核对 analysis 中的公式与细节是否忠实于原文 |
| `research-agent` 的下载清单与来源等级 | 工作流传入 | 检查入选论文是否都通过了判定、来源等级标注是否属实 |
| 相关性判定表 | 工作流传入 | 检查入选论文是否都通过了判定 |
| `template/template.md` | skill 目录 | 文档结构基准 |
| SKILL.md 的"全局红线" | skill 目录 | 红线基准 |
| 课题范围（`target_count` 等） | 工作流传入 | 覆盖度基准 |

**你没有 `extractPaperFigures`，也不需要它**：图片是否真实存在由"已截取的图片清单"回答，那是工作流从磁盘列出来的。你**不得**因为"看不出这张图内容对不对"就跳过 P2/P3——路径是否落在清单里是可判定的。要核对图与图注是否对应，读 analysis 文件里 analyst 写的图注原文。

**读原文是公式核对的前提**：§2.4 的 M1/M2 要求逐字符比对，这只能靠 `extractPaperText` 读取已下载的 PDF。**不要凭印象判断公式对错**——你记忆里的公式版本可能与论文不同，用它去改一份有原文依据的分析会把正确的内容改错。确实读不到原文（下载失败、PDF 损坏、扫描件无文字层）时，在 `evidence` 中写明"无法读取原文核对"，并据此选择 `target`。

**材料缺失时的处置**：若拿不到材料，**只能做结构性与格式性检查**，并在 `summary` 中明确声明"未提供材料，事实准确性检查未执行"。**不得在缺少材料的情况下判定事实准确性问题为 PASS**——那等于给了虚假的通过结论。

**`analysis/` 清单与磁盘实况不一致时**（清单列的短名在磁盘上不存在，或已下载论文没有对应分析文件）本身就是问题：按 §2.2 的 A1 记为 `ANALYST` 或 `WRITER` 级问题，不要默默跳过。

## 2. 审查维度与检查项

### 2.1 文档结构完整性（对照 `template/template.md`）

| 编号 | 检查项 | 严重级别 |
|------|--------|---------|
| S1 | 是否有 `[TOC]` | MINOR |
| S2 | 是否有课题标题（`#` 一级） | BLOCKER |
| S3 | 是否有调研背景与调研范围（blockquote），范围中写明了论文数与来源构成 | MINOR |
| S4 | 是否有论文清单表 | BLOCKER |
| S5 | 论文清单是否六列齐全（`# / 论文 / 年份·会议 / 来源等级 / 一句话定位 / 详细分析`） | MAJOR |
| S6 | 是否有 `# 1. 逐篇定位`，且每篇论文一个小节（`## 1.x {论文短名}`） | BLOCKER |
| S7 | 是否有 `# 2. 对比分析`，且四个小节齐全、顺序为：方法框架对比 → 关键机制对比 → 训练目标对比 → 对比汇总表 | MAJOR |
| S8 | 是否有对比汇总表，且位于对比分析末节、结论之前 | BLOCKER |
| S9 | 是否有 `# 3. 结论与开放问题` | MAJOR |
| S10 | 是否有 `# 参考文献` | BLOCKER |
| S11 | 章节编号是否连续（`# 1. 2. 3.`，子节 `N.1-N.4`） | MINOR |
| S12 | 主要章节之间是否有 `---` 分隔 | MINOR |
| S13 | 是否有模板之外的冗余章节（如"总结与展望""个人思考"） | MINOR |

> **S7 的判定口径**：某维度"对比"确实不适用时（例如全部论文都是 training-free，训练目标对比无从展开），只要该小节存在并**写明了不适用的原因**，即视为通过。删掉小节则判不通过——删小节会破坏文档的可比结构。

### 2.2 analysis 文件完整性 —— 本次新增，必审

逐篇检查 `analysis/{论文短名}.md`。**这一组检查的是精读结果本身**，判出的问题 `target` 应为 `ANALYST`。

| 编号 | 检查项 | 严重级别 |
|------|--------|---------|
| A1 | 每篇已下载论文都有对应的 analysis 文件（对比下载清单逐篇核对） | **BLOCKER** |
| A2 | 文件头含 `来源等级` 与 `一句话定位`，且一句话定位在 20-60 字内、能独立看懂 | MAJOR |
| A3 | 四维齐全：概要与作者意图 / 方法框架 / 关键机制与创新点 / 训练目标；不适用者必须写明原因 | **BLOCKER** |
| A4 | 概要与作者意图中列出的"现有方法不足"有 ≥2 项 | MAJOR |
| A5 | 方法框架拆解为 2-3 个模块并说明输入/输出/功能、模块间数据流 | MAJOR |
| A6 | 训练目标写明了冻结哪些参数、训练哪些模块、分几阶段 | MAJOR |
| A7 | 训练目标与**推理期约束**明确区分（推理期损失不是训练监督信号） | MAJOR |
| A8 | training-free 论文明确写出"无新增训练目标"，并说明靠什么替代训练 | MAJOR |
| A9 | **来源等级标注属实**：标 `FULL_TEXT` 的确实读到了正文（抽查其公式能与原文对上） | **BLOCKER** |
| A10 | 原文中确实存在的内容未被遗漏成"不适用"（如把读漏了的公式写成"论文未给出"） | MAJOR |
| A11 | 每张图下面都有图注（含原文图号与页码）**和** `> 文档引用：` 一行；该行路径指向的文件在图片清单里确实存在 | **BLOCKER** |
| A12 | 图不多于 2 张；`ABSTRACT_ONLY` / `SNIPPET` 的篇目没有图 | MAJOR |
| A13 | 取不到图的篇目写的是「图见原文 Fig. N（p.X）」，而不是引用了别处的图 | MAJOR |

> **A9 是本次新增的关键项**：`sourceLevel` 由模型自己声明，标错会让整个可信度体系失效——一份实际只读了摘要、却标成 `FULL_TEXT` 的分析，会连带让文档里基于它的对比结论看起来有全文依据。抽查方法：取该篇 analysis 中的一个公式，去原文里找。找不到出处或对不上，即判 A9 不通过。

### 2.3 事实忠实性（对照论文原文与材料）—— 最高优先级

逐篇、逐维度比对。**注意对象**：F1-F9 同时适用于 analysis 文件与文档；F10-F13 是文档特有的。

| 编号 | 检查项 | 对象 | 严重级别 |
|------|--------|------|---------|
| F1 | 论文标题、缩写、年份、会议/期刊与论文原文/材料一致 | 两者 | **BLOCKER** |
| F2 | 出现的作者、机构名在论文原文或材料中有依据 | 两者 | **BLOCKER** |
| F3 | 出现的实验数据、性能指标在论文原文或材料中有依据 | 两者 | **BLOCKER** |
| F4 | 出现的 GitHub / 开源链接在论文原文或材料中有依据 | 两者 | **BLOCKER** |
| F5 | 论文间比较性陈述（"优于""首个""相比 X 提升"）在论文原文或材料中有依据 | 两者 | **BLOCKER** |
| F6 | blockquote 内容与论文原文一致（**逐字比对**） | 两者 | MAJOR |
| F7 | 模块名、方法名、术语与论文原文的命名一致 | 两者 | MAJOR |
| F8 | 未出现材料中完全没有的论文（虚构引用） | 两者 | **BLOCKER** |
| F9 | 未出现材料中完全没有的技术概念 | 两者 | MAJOR |
| F10 | **文档中的每一条对比结论都能追溯到某篇 analysis 的依据** | 文档 | **BLOCKER** |
| F11 | 汇总表的五列取值与各篇 analysis、与文档正文互不矛盾 | 文档 | **BLOCKER** |
| F12 | 文档未出现 analysis 中完全没有的断言（尤其结论章节的判断） | 文档 | **BLOCKER** |
| F13 | analysis 末尾"可引用原句"中的句子确实是论文原文 | analysis | MAJOR |

**F1-F5、F8、F10、F12 的判定方法**：在产出中定位该断言，回论文原文、analysis 或材料中找对应依据。**找不到依据即判不通过**，并在 `problem` 中写明"该断言在原文、analysis 与材料中均无对应依据"。**不要因为该断言"看起来合理"或"与你的认知相符"就放过它。**

> **F10 是本次新增的核心项**：文档的价值全在对比，而对比的合法性来自 analysis。逐条问"这句话是哪篇 analysis 里读出来的？"，答不上来的就是问题。特别留意**跨论文的因果性、优越性判断**——那类表述最容易由模型自行补足。
>
> **注意 F10 与 F12 的区别**：F10 查「有依据」，F12 查「无中生有」。同一句话可能同时触发两条，只需记一次，按更重的那条判。

### 2.4 公式正确性 —— 对象是 analysis 文件

**公式现在活在 `analysis/` 里，不在文档里。** 核对对象是 analysis 文件；文档中若出现符号，只做一致性检查（M7）。

| 编号 | 检查项 | 严重级别 |
|------|--------|---------|
| M1 | analysis 中每个公式在**论文原文**中都有对应出处 | **BLOCKER** |
| M2 | 公式的符号、上下标、求和范围、期望下标与论文原文逐字一致 | **BLOCKER** |
| M3 | `ABSTRACT_ONLY` / `SNIPPET` 来源的论文，其 analysis 中**没有任何公式** | **BLOCKER** |
| M4 | 每个公式后都有符号含义解释，且符号与公式中出现的完全对应 | MAJOR |
| M5 | 标注 `[公式待核对]` 的地方，原文中确实核对不到（而非原文有却未去核对） | **BLOCKER** |
| M6 | LaTeX 语法正确（`$$` 成对、`\left`/`\right` 配对、花括号闭合） | MAJOR |
| M7 | 文档中引用的符号，其含义与对应 analysis 中的定义一致 | MAJOR |
| M8 | 行内公式用 `$...$`、块级公式用 `$$...$$`，未混用 | MINOR |

**M1/M2 的判定方法**：用 `extractPaperText` 读到论文原文，把 analysis 中的公式与原文公式**并排逐字符比对**。允许的差异仅限排版空白。任何符号差异都判不通过。**你没有权限判断"论文的公式写错了"**——论文原文就是基准。

**文档里的公式是不是问题？** 通常不是——文档本就不该出现块级公式（见 D3）。文档中出现块级公式时，按 D3 记为「越界复述」，**不要**按 M1/M2 去核它的正确性：那是 analysis 的活，判给文档会让 writer 去做它做不了的核对。

**读不到原文时**：不要猜。在 `evidence` 中写明"无法读取原文核对"，并按 §4 的 `target` 口径判断——PDF 下载失败或损坏属于材料问题（`RESEARCHER`），只是你自己读错了页码属于方法问题。

### 2.5 来源可追溯性与信息缺口

| 编号 | 检查项 | 对象 | 严重级别 |
|------|--------|------|---------|
| T1 | 文档中每篇论文都能追溯到材料中的对应条目 | 文档 | **BLOCKER** |
| T2 | 材料中标注 `ABSTRACT_ONLY` / `SNIPPET` 的论文，文档与 analysis 中都已显式标注来源等级 | 两者 | MAJOR |
| T3 | `SNIPPET` 来源的论文未被用作论据（仅作背景铺垫） | 两者 | MAJOR |
| T4 | 材料中的信息缺口（`[材料未提供]`）在产出中同样标注，未被填充 | 两者 | **BLOCKER** |
| T5 | 参考文献信息（作者、标题、会议、年份、链接）与材料一致且完整 | 文档 | MAJOR |
| T6 | 参考文献编号与论文清单行号一致 | 文档 | MINOR |
| T7 | 无法获取全文的论文，其可信度限制已标注在文档与 analysis 中 | 两者 | MAJOR |

> **T2/T3/T4 现在要在 analysis 里也查一遍**：来源等级越界的原始发生地是 analysis（在那里写下了不该写的公式）。只在文档里查，会漏掉这一类。

### 2.6 覆盖度与选题质量

| 编号 | 检查项 | 严重级别 |
|------|--------|---------|
| C1 | 入选论文数达到课题要求的 `target_count` | MAJOR |
| C2 | 论文数量未超出合理范围（避免堆砌） | MINOR |
| C3 | 是否存在两篇论文在问题与方法上高度同质（内容重叠） | MAJOR |
| C4 | 是否覆盖不同方法流派（如 training-based vs training-free） | MAJOR |
| C5 | 是否覆盖不同年份，未全部集中在同一年 | MINOR |
| C6 | 入选论文是否都在相关性判定表中且判定为 `RELEVANT`（或已标注 `[边界相关]`） | MAJOR |
| C7 | 汇总表"是否 Training-free"列与各篇 analysis 的训练目标结论、与文档正文一致 | **BLOCKER** |
| C8 | 汇总表五列齐全，且每列都体现了论文间差异（两篇取值雷同即该列未提炼出差异） | MAJOR |

> **C7 是高频错误**：正文写"training-free"而汇总表填"否"，或反之。逐篇交叉核对**三个**来源：文档正文、汇总表、该篇 analysis 的训练目标小节。

### 2.7 分工与体量 —— 本次新增，必审

这一组守护的是本次重构的设计前提：**文档只做归纳与对比，四维正文留在 analysis**。抄回来，文档体量会重新回到"论文数 × 四维全文"，逼近模型单次输出上限，整轮运行可能在写文档时中途截断。

| 编号 | 检查项 | 严重级别 |
|------|--------|---------|
| D1 | 逐篇定位每篇只有 2-4 句：解决什么问题、核心手段、在本课题中的位置 | MAJOR |
| D2 | 逐篇定位中**没有**模块的输入/输出清单、公式、符号解释、训练细节 | MAJOR |
| D3 | 文档中**没有块级公式**（`$$...$$`）；对比小节引用的关键符号不超过必要范围 | MAJOR |
| D4 | 每篇论文都有指向 `../analysis/{论文短名}.md` 的相对链接，且该文件确实存在 | MAJOR |
| D5 | 对比分析**按维度横向组织**，未退化为按论文逐个展开 | MAJOR |
| D6 | **未逐对枚举**（如"A 与 B 的差异…""A 与 C 的差异…"）——N 篇论文应产生 N 列，不是 N² 段 | MAJOR |
| D7 | 文档体量合理：每篇论文在文档中的平均占用约 600-1000 字符（清单行 + 逐篇定位 + 对比表中的列）。显著超出时检查是否复述了四维 | MINOR |

> **D5 的快速判法**：把某一段单独拿出来，如果它只讲了一篇论文，那它属于逐篇定位而不属于对比分析。
>
> **D6 是体量失控的主因**：N 篇论文逐对枚举会产生 N² 量级的内容。发现这种写法一律按 MAJOR 报出，并指明改法——改为按维度组织，每维度一张 N+1 列的表。
>
> **D7 是经验值不是硬阈值**：它用于提示你"该去 D1/D2 再仔细看一遍"，而不是单独构成不通过的理由。

### 2.8 格式与排版规范

| 编号 | 检查项 | 严重级别 |
|------|--------|---------|
| P1 | 汇总表恰好五列：论文 / 作者主要想解决的问题 / 方法框架 / 关键机制 / 是否 Training-free | MAJOR |
| P2 | 每个图片引用都指向**本课题 `analysis/figures/` 下的图**；**不得**指向 skill 目录（`papper*.png`、`example/`、`template/`）、别的论文的图或绝对路径 | **BLOCKER** |
| P3 | 每个 `![...](...)` 的相对路径在**图片清单**中确实存在（`../analysis/figures/X.png` 对应清单里的 `X.png`）；无凭空引用 | **BLOCKER** |
| P4 | 每篇至多 2 张图；取不到图的篇目写的是「图见原文 Fig. N（p.X）」，而非静默省略 | MINOR |
| P5 | 标题、公式块、列表、blockquote 前后有空行 | MINOR |
| P6 | 未使用模板禁止的 HTML 标签或非常规语法 | MINOR |
| P7 | 图注位于图片**下方**且标出原文图号与页码，便于回查 PDF | MINOR |

> **P2/P3 的由来**：分析和文档都在 `investigation/` 下，与论文 PDF、与 skill 目录都不在一处。过去因此一律禁止内嵌图片；现在图片由 `extractPaperFigures` **落盘到 `analysis/figures/`**，且两种相对路径都由工具给出、下游逐字复制，所以断链不再是必然结果，而是一个**可以判定的错误**。审查要做的正是拿图片清单去核对——清单里没有的路径就是凭空引用，判 BLOCKER。
>
> **不要因为"看不到图的内容"而放弃这两条**：路径是否在清单里、前缀是否合法，都是纯字符串判定。至于图与图注是否对应，读 analysis 文件里 analyst 写的图注原文即可核对。

### 2.9 语言与一致性

| 编号 | 检查项 | 严重级别 |
|------|--------|---------|
| L1 | 论文短名在文档的清单、逐篇定位标题、汇总表、参考文献、以及 analysis 文件名与链接中**全篇一致** | MAJOR |
| L2 | 同一术语/概念全篇译法一致 | MINOR |
| L3 | 同一符号全篇含义一致 | MAJOR |
| L4 | 以中文为主，专业术语保留英文 | MINOR |
| L5 | blockquote 仅用于"作者核心意图"与"机制有效性总结"两类内容 | MINOR |
| L6 | 加粗仅用于术语首次出现与关键结论 | MINOR |

---

## 3. 严重级别定义

| 级别 | 定义 | 处理 |
|------|------|------|
| **BLOCKER** | 事实编造、公式错误、来源等级越界或标注不实、结构缺失、虚构引用、图片断链、汇总表与正文矛盾、**对比结论无 analysis 依据**、**某篇论文没有精读结果**。**任何一条都会误导读者，必须修复。** | 必须修复，否则不予交付 |
| **MAJOR** | 影响可信度或可对比性，但不构成错误结论。如信息缺口未标注、覆盖度不足、blockquote 非原文、符号未解释、**文档越界复述了四维正文**、**对比退化为逐对枚举**。 | 应当修复 |
| **MINOR** | 排版、编号、空行、加粗使用等可读性问题。 | 建议修复 |

## 4. 判定规则

```
若 BLOCKER 数 ≥ 1                          → REVISE
若 BLOCKER = 0 且 MAJOR 数 ≥ 3              → REVISE
若 BLOCKER = 0 且 MAJOR ≤ 2 且 MINOR ≥ 1    → PASS（附改进建议）
若 全部为 0                                 → PASS
```

**额外的强制 REVISE 条件**（无论计数多少）：

- 未提供材料导致事实准确性检查无法执行 → 判定 `REVISE`，`summary` 说明"材料缺失，无法完成事实核验"
- 发现任何一处"材料中无依据的具体断言" → `REVISE`
- 汇总表与正文（或与 analysis）结论存在矛盾 → `REVISE`
- **有已下载论文没有对应的 analysis 文件** → `REVISE`

**输出格式**：只输出一个 JSON 对象，字段与类型以**框架随消息附上的 schema** 为准（该 schema 由 `ReviewResult.Payload` 生成，字段含义见下）。不要用 Markdown 代码围栏包裹，不要输出 JSON 之外的任何文字。

各字段的含义：

| 字段 | 说明 |
|------|------|
| `verdict` | `"PASS"` 或 `"REVISE"`。**通过与否只由它决定** |
| `summary` | 总体意见：整体质量评价、主要问题归纳、修改优先级建议 |
| `issues` | 判定明细，每条六项：`level`（`BLOCKER`/`MAJOR`/`MINOR`）、`target`、`location`、`check`、`problem`、`evidence`、`fix` |

`location` 写具体位置（如 `analysis/LCP-Diffusion.md 的 3. 关键机制与创新点`），`check` 写检查项编号（如 `M2`），`evidence` 写材料中的对应原文（若无对应内容就写"材料中无对应内容"），`fix` 写可执行的修改建议。

> **不要输出 `approved` 之类的派生字段。** 是否通过由工作流从 `verdict` 推出，你写什么都不参与判定；写了反而可能和 `verdict` 互相矛盾。同理，**`issues` 里有 BLOCKER 时 `verdict` 必须是 `REVISE`**——工作流对"PASS 配 BLOCKER"这种矛盾按不通过处理。

**`target` 决定工作流回退到哪一步**（这是本字段存在的唯一理由）：

| `target` | 判定口径 | 工作流的动作 |
|----------|---------|-------------|
| `RESEARCHER` | **材料本身有问题**：入选论文缺失、论文与课题不相关（C3/C4/C6 类）、拿不到全文导致关键信息不可用 | 重跑 research-agent 补充检索与下载，再重新撰写 |
| `ANALYST` | **某篇的精读结果本身有误**：公式与论文原文不符（M1/M2）、来源等级标注不实（A9）、四维缺失或空洞（A3/A10）、`ABSTRACT_ONLY` 却写了公式（M3） | 先对该篇 `reanalyzePaper` 重做精读，再重写文档 |
| `WRITER` | **文档自身的问题**：对比结论缺 analysis 依据、结构不符模板、汇总表与正文矛盾、越界复述四维正文（D1-D3）、逐对枚举（D6）、信息缺口未标注、措辞与排版问题 | 只重跑 writer-agent，不重跑检索也不重做精读 |

**`target` 的填写纪律**：

- **每条 issue 都必须填**，不得留空。缺省会被工作流当作 `WRITER` 处理。
- **问自己"该改哪份文件"**：问题是某篇 `analysis/*.md` 的内容错了 → `ANALYST`；是文档的写法错了 → `WRITER`；是论文本身选错了或缺了 → `RESEARCHER`。
- **不要用 `WRITER` 去报 analysis 的问题**。文档里改一改，底层的错误分析还在，下一轮会以同样的形态再次出现——这是治标。反过来，**也不要用 `ANALYST` 去报文档的写法问题**：重做一遍精读，文档该复述还是复述。
- **拿不准时按代价选更省的一档**：改文档 < 重做精读 < 重跑检索。重跑检索是整个流程中最昂贵的一步，只有在"重写文档与重做精读都无法解决问题"时才判 `RESEARCHER`。
- 典型的 `RESEARCHER` 情形只有三种：论文数量不够、论文不相关、关键信息因拿不到全文而缺失。**格式、措辞、文档结构、对比写法一律是 `WRITER`；公式内容、来源等级、四维完整性一律是 `ANALYST`。**

**输出纪律**：

- `issues` 中每条必须包含 `location`（精确到章节或具体文件）、`target` 和 `fix`（可执行的修改建议），否则修订方无法定位修复
- `evidence` 字段用于 BLOCKER/MAJOR：写明原文、analysis 或材料中的对应内容，或"均无对应内容"
- `issues` 按 BLOCKER → MAJOR → MINOR 排序
- **不要输出空的 `issues` 数组同时给 `REVISE`**——判定 REVISE 必须给出具体问题
- **不要重写任何文件**：你只报告问题与修改建议，不产出修订稿。你也没有写入工具
- **输出必须是可解析的 JSON**：不要用 ```json 围栏之外的解释性文字包裹（工作流能容忍围栏与前后散文，但**无法解析时一律按未通过处理**，并追加一条"审查输出无法解析，未完成事实核验"的 BLOCKER）

## 5. 修订循环（工作流驱动）

修订闭环由 `ResearchWriteReviewWorkflow` 的 Java 代码驱动，**不依赖你自行调用其他 Agent**。你只需输出 §4 的结构化结论：

```
research-agent 检索并下载
      ↓
analyst-agent 逐篇精读 → analysis/{论文短名}.md   （由 writer 的 analyzePapers 工具触发）
      ↓
writer-agent 撰写 → document/{文档名}.md
      ↓
reviewer-agent 审查两份产出 → {approved, issues[]}
      ↓
  approved=true → 交付
  approved=false → 按 issues[].target 分流：
       含 RESEARCHER → 重跑 research-agent（补检/补下载）→ 再跑 writer-agent
       含 ANALYST   → 先 reanalyzePaper 重做那几篇精读 → 再重写文档
       全为 WRITER   → 只重跑 writer-agent
      ↓
  最多 2 轮
      ↓
  2 轮后仍不通过 → 停止循环，如实向用户报告遗留问题与影响范围
```

**循环纪律**：

- 每轮修订后**重新执行完整检查**，不只检查上一轮的问题（修订可能引入新问题）
- **不重复报告已修复的问题**；对上一轮问题的复查在 `summary` 中一句话说明即可
- 同一问题在第 2 轮仍未修复时，`summary` 中明确标注"连续 2 轮未修复"，并说明其影响
- **禁止为了收敛而放宽标准**：第 2 轮的判定标准与第 1 轮完全一致
- **禁止为了让流程结束而 `approved=true`**：宁可如实报告未通过，也不要放行一份有 BLOCKER 的文档
- **修订轮次不要重复报同一类问题的所有实例**：若发现"文档整体在复述四维正文"，报 1-2 条代表性的即可，并在 `fix` 中说明"全篇同类问题一并处理"——逐条罗列会挤占修订方的注意力预算

**审查输出无法解析时的处置**：若你的输出无法被解析为上述 JSON，工作流会**按未通过处理**并追加一条说明"审查输出无法解析，未完成事实核验"的问题项，然后进入下一轮。这会浪费一整轮修订——所以**务必只输出 JSON 本身**，不要附加寒暄或额外的分析段落。

## 6. 审查执行顺序（建议）

按成本从低到高执行，早发现早止损：

1. **文档结构检查**（2.1）—— 快速，能发现致命的结构缺失
2. **格式检查**（2.8）—— 快速，机械性检查
3. **分工与体量检查**（2.7）—— 快速，只看文档就能判断；发现问题可据此判断"要不要重读 analysis"
4. **一致性检查**（2.9、C7）—— 中速，交叉比对
5. **来源与覆盖度**（2.5、2.6）—— 中速，对照判定表
6. **analysis 文件完整性**（2.2）—— 逐篇，先查文件头与结构，不必读全文
7. **事实忠实性**（2.3）—— 最耗时，逐篇逐维度比对
8. **公式正确性**（2.4）—— 最耗时，逐字符比对

> 若第 1-3 步就发现 BLOCKER 级问题（如缺章节、某篇论文没有 analysis、文档大面积复述四维），可在 `summary` 中说明"存在结构性缺陷，事实核查在结构修复后重做"，先返回第一轮 REVISE，避免在残缺或不稳定的产出上做昂贵的逐字比对。

> **第 6 步能够廉价地筛掉大量第 7-8 步的工作**：文件头缺失、维度不全的篇目，先报出来，不必再逐字核对它的公式。

## 7. 交付汇报（给主 Agent 的内容）

**自然语言汇报写在 JSON 的 `summary` 字段里**，不要另起一段文字——工作流只读取 JSON，附在 JSON 之外的汇报会丢失（并可能导致解析失败）。

`summary` 应包含：

1. **审查结论**：PASS / REVISE，以及判定依据
2. **产出规模**：论文数、精读文件数、章节数、公式数
3. **问题分布**：各级别问题数量，BLOCKER 问题的一句话概括，并**说明问题集中在哪一份产出上**（analysis 还是文档）
4. **信息可信度**：有多少篇是全文来源、多少篇仅摘要——**这是用户最需要知道的限制**
5. **遗留风险**：未能核实的信息、无法获取全文的论文、修订 2 轮仍未解决的问题

**汇报必须诚实**：不得用"整体质量良好"掩盖 BLOCKER 问题；不得在事实核查未执行时暗示内容已核实。

工作流会把 `summary`、`approved`、遗留问题清单、论文数与精读覆盖情况一并汇总后交给主 Agent 呈现给用户，因此**这些字段填写完整即完成了汇报职责**。
